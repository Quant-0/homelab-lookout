Chapter 1

Getting started

Lookout runs on one machine in your lab and you open it in a browser, for example https://lookout.home.arpa:8443. Ask whoever installed it for the address and the admin login.

Sign in

Enter the admin user name and password. After five wrong passwords you have to wait, first 30 seconds, then longer each time, up to an hour.

  • A normal sign-in lasts 12 hours (2 hours without use).
  • Keep me signed in: 30 days, ending after a week without use. Restarts and updates don't sign you out.
  • A few risky changes ask for the password again if you haven't typed it in the last 15 minutes: backups, alert channels, the web server and making things public.

Passkeys

Once you have added one (chapter 15), Sign in with a passkey uses Face ID, Touch ID, Windows Hello or a security key. The password keeps working. Passkeys work on the dashboard's domain name, not on its IP address.

Remember this device for viewing

For 30 days, that device can look at every page without the password, but it can't change anything. Use it for a wall tablet.

Trust the certificate (once per device)

Lookout makes its own small certificate authority, so the browser warns you until the device trusts it. Download it from /ca.crt or Admin → Server → Download CA certificate, check the fingerprint against the one shown under Certificate, and import it:

DeviceHow
iPhone / iPadOpen the file → Settings → Profile Downloaded → Install. Then General → About → Certificate Trust Settings → turn it on.
AndroidSettings → Security → Encryption & credentials → Install a certificate → CA certificate.
WindowsDouble-click → Install Certificate → Local Machine → Trusted Root Certification Authorities.
macOSDouble-click → Keychain Access (System) → open the certificate → Trust → Always Trust.
LinuxCopy to /usr/local/share/ca-certificates/ and run sudo update-ca-certificates.

The certificate authority can only vouch for this one server, so trusting it doesn't let it pretend to be other websites.

Install it as an app

  1. Trust the certificate first (above).
  2. Android: Chrome menu ⋮ → Install app. iPhone: Safari → Share → Add to Home Screen. PC: the install icon at the end of the address bar.
  3. Open the app and sign in with Keep me signed in ticked. On an iPhone, sign in inside the app.
  4. For alerts on the phone, turn on push in the app (chapter 12).

The app icon is your logo (chapter 14). When the server can't be reached, the app says Can't reach the dashboard and opens by itself once it is back.

Chapter 2

Finding your way

The pages are in the bar at the top: Home · Rack · Services · VMs · Energy · Docs · Updates · Log. On the right are Search and your avatar: click it for Admin, Look on this device, the User guide and Log out.

Docs and Updates appear when you're signed in or on a remembered device. Log and Admin are for the admin only.

Search

Press Ctrl K or / anywhere. It finds devices, services, VMs, Docs sheets and pages (including the text inside them), IP reservations and settings. Use ↑ ↓ to choose, Enter to open and Esc to close.

Your own look

The palette button changes the look on this device only: Auto, Dark, Light, more themes and an accent colour. Everyone else keeps the owner's look from Admin. Use the owner's look goes back.

Chapter 3

Home

Home answers one question: is everything all right? It shows problems first, then power and the internet, then every device drawn the way it looks.

At the top: the summary and "Needs you"

The pill says how many faults and things to watch there are, or All normal. Below it, one row per problem, worst first, with how long it has been going on. Click a row to open the device. A connection that stops answering is listed only after 2 minutes, so a single slow reading doesn't raise an alarm.

  • Acknowledge (admin): someone is on it. The problem stays until it clears, but no more reminders are sent. The row says Acknowledged by …. You can also acknowledge from the alert message itself (chapter 12).
  • Snooze (admin): the problem leaves the top of Home and the wall display for 1 day or 1 week, but the device still shows it and alerts are still sent. A warning that turns into a fault comes back by itself.
  • Behind core-switch: when a switch or host is down, what is reached through it is grouped under it, muted, with one alert for the cause (chapter 10).
  • Maintenance and Alerts muted: problems during planned work, or on something whose alerts are switched off. Shown, not sent.
  • Public IP changed: shown until an admin closes it. It stays in the Log.

Power and Internet

Power shows what the lab draws now, today's and this month's cost, and a graph of the last 24 hours. Power comes from server controllers, smart plugs, UPSes and PoE, and estimates for the rest. Click it for the details and the Energy report.

Internet comes from your gateway (UniFi or Omada), with your provider and its logo. The public IP is only shown to people who are signed in.

Devices and their details

Each device has a tile with its drawing, one status (OK, Warning, Fault, Offline, Unreachable or Maintenance), its worst problem or model, and one key number. Click a tile for the details: problems first, then numbers, graphs, power supplies, fans, drives, ports, VMs and containers, with buttons for its Docs sheet and Admin.

One quiet line at the bottom counts services up, VMs running and updates available. Each is a link.

Chapter 4

Rack and patch cables

The rack is drawn to scale with live lights: the drives your servers really have, switch ports lit by link and PoE, status LEDs. A device with a problem gets a red or amber outline.

  • Realistic / Schematic switches between the drawing and plain blocks with names, status and power.
  • Click a device to see its details. Devices outside the rack (access points, cameras) are listed below it.

Patch cables

Cables shows or hides the patch cables in your browser. They are off at first, so the rack stays clean.

To draw them, sign in and press Patch:

  1. Pick a colour in the bar above the rack.
  2. Click a port on a switch, gateway or patch panel.
  3. Click the port at the other end. The cable is saved.
  4. Click a cable to change its colour, add a label, or Remove it.
  5. Done leaves patch mode.
Every cable change is written to the Log. Removing a device or patch panel from the rack also removes its cables. The wall display shows cables when you tick Patch cables in its Customize panel.
Chapter 5

Services and the status page

Your self-hosted apps, grouped the way you like, each with a status dot and up to four live numbers. Click a card to open the app.

  • The dot is green when the service's status check passes: a web page, a ping, a TCP port or a DNS lookup (chapter 11). Point at it for the response time.
  • For an https:// service the certificate's expiry is watched too: a warning two weeks before, critical the last three days.
  • The numbers come from each app's integration: movies and series in Jellyfin, queued downloads, blocked queries, photos in Immich, and so on.
  • Customize (admin) drags services between groups, renames groups, sets columns and hides services.

The status page

A public page for the people who use your services: whether each one is up, its uptime over 90 days (30 on a phone), and planned maintenance. It shows no links, addresses, devices or VMs.

Switch it on in Admin → Dashboard. It works while the dashboard itself stays private, so you can share it instead of the dashboard.

Chapter 6

VMs and containers

Every VM and container on your Proxmox hosts, and every Docker container, on one page: VMs in the top bar.

  • Search by name, ID, address or OS, and filter Running, Stopped or Backup (no backup, or an old one). Click a column heading to sort (by ID at first). Settings opens where VMs are set up.
  • The disk is a container's own disk, or for a VM with the QEMU guest agent its fullest filesystem. The address comes from the guest agent too.
  • Last backup is the newest backup Proxmox has of the guest, on any backup storage. A guest is overdue when its newest backup is older than its backup job's interval plus a day (a monthly job allows 32 days); that raises a Backup failed warning.

Containers

Containers come from a Docker host through a read-only socket proxy, or from Portainer (chapter 10). A Portainer card under Services has Show its containers, which adds that connection for you. A container that keeps restarting, one that stopped although it should run, or one that fails its health check shows under Needs you and sends a Container problem alert. A container you stopped by hand doesn't count, and the label lookout.ignore=true leaves one out.

Chapter 7

Energy report

How much the lab used and what it cost, per day or per month, split per device, priced with your own electricity plan and grid tariff.

  • Month / Year switches between days in a month and months in a year; ‹ › step through periods.
  • Point at a bar for that day. Show as table gives the same numbers as a table.
  • Per device separates measured power (server controllers, smart plugs, PoE) from estimates you entered.
  • Downloads: Excel (NO) opens straight in Norwegian Excel; CSV is for everything else.
Chapter 8

Docs, Updates, Log and the report

Docs

  • Server sheets: model, serial, CPU and memory, disks, rack position, addresses and switch port fill in by themselves. Edit notes adds your own.
  • Network plan: networks and IP reservations, importable from UniFi.
  • Pages: your own pages in Markdown, with a history of the last 50 versions and Recently deleted.
  • Edit menu arranges the menu in groups.
Docs are not for passwords. Link to your password manager instead.

Updates

One list for Proxmox, TrueNAS and its apps, UniFi firmware, Synology and most services. It is checked every night; Check now checks right away.

Nothing is ever installed from Lookout. Update on the device itself, then press Check now.

Log

Everything that happens, newest first, grouped by day: changes in Admin and Docs (Title: Homelab → My Lab), devices found, problems starting and clearing, notifications sent, acknowledgements, snoozes, IP changes, patch cables, sign-ins, update checks and backups.

Filter by category, search, and Download CSV. Entries are kept for a year and go into backups. Passwords are never written to it.

Monthly report

Report in the top bar sums up a month: the uptime of every service and device, the problems and how long they took to clear, energy and cost, and how each storage grows with when it will be full at that pace. A storage that will be full within 30 days also shows under Needs you. Print or save as PDF makes a clean copy.

Incidents

Incidents at the top of the Log lists every problem from when it appeared to when it cleared: how long it lasted, who acknowledged it and when, and whether it was behind another outage or during maintenance. Open only shows the ones still going on, each with an Acknowledge button. Incidents are kept for a year.

Configuration history

History at the top of the Log lists every change made in Admin, with who made it and what it changed. Undo puts back only what that change touched; a deleted device comes back with its connections and stored passwords. If something was changed again since, it says what and asks first. Go back to here puts the whole configuration back as it was right after that change. An undo can be undone too, and both ask for your password if you haven't typed it in the last 15 minutes. The admin password, passkeys and the web server's ports are never part of it, so an undo can't lock you out. Versions are kept for 90 days on the server.

Chapter 9

Wall display

One screen for a tablet or TV, readable from across the room. Open it from Wall display on Home, or at /wall.

  • Needs you shows one problem at a time, eight seconds each, with the full list beside it.
  • The buttons by the clock fade out when nobody touches the screen; touch it or move the mouse to bring them back.
  • Tap anything to open it on Home. The full-screen button keeps the screen awake where the browser allows it.
  • For a wall tablet, sign in once with Remember this device for viewing; it then shows the wall without a password and can't change anything.
Chapter 10

Admin: devices

Admin has ten tabs in three groups: Monitoring (Devices · Services · Alerts · Check-ins & maintenance), Dashboard (Dashboard · Look · Power & cost) and System (Backups · Sign-in & security · Server). On a phone, the section menu at the top switches between them. Passwords, tokens and keys are entered here and nowhere else; they are stored encrypted and never shown again.

Add a device from the catalog

  1. Press Add device.
  2. Choose the brand, then the type, then the model. Search works from any step.
  3. Add this device fills in the size, front, drive bays, typical power and the right connection.
  4. Give it a name, fill in the connection, press Test, then Save device.

UniFi switches, access points and cameras appear by themselves once the console is added.

Find devices scans your own networks and lists what it recognises (Proxmox, TrueNAS, iDRAC, Synology, UPSes, plugs, Docker and web apps), each with Add device or Add service to open the form filled in. No password is tried, and nothing is added until you choose it.

Self-signed certificates

Choose Pin SHA-256 fingerprint and press Fetch certificate. Lookout checks the fingerprint before sending the password. If it changes later (a firmware update), the device stops with fingerprint mismatch; nothing was sent. Find out why, then fetch and save the new one.

More

  • Power reading from: Automatic (the controller, then a smart plug, then the estimate), one of them, or Not counted. Each device is counted once.
  • Estimated power for devices without a power sensor.
  • In the rack with height and lowest U, outside the rack, or not placed. Look and Drive bays change the drawing.

Linux agents

A Lookout agent on a VM, container or Linux machine reports what Proxmox can't see: memory as Linux counts it, load, every filesystem, failed and watched systemd services, pending updates (and security fixes, and a needed reboot) and temperatures. In Admin → Devices → Linux agents, Add agent, choose what it runs on (a VM from Proxmox, a device or a new one), and run the command it shows on the machine. On the machine: sudo lookout-agent status, test, watch add nginx, update and uninstall. It only reports, and never updates itself.

Reached through

Each device has Reached through: the switch, gateway or host it depends on. Automatic uses what UniFi reports (an access point hangs off its switch); for servers, choose it yourself. When that device is down, everything behind it (devices, their services and check-ins) is grouped under it on Home as Behind core-switch, their tiles say Unreachable, and only one alert is sent, naming what is behind it.

Alerts for this device

  • Mute stops messages for the device and the services and check-ins on it. Its problems still show, marked Alerts muted. For planned work, use maintenance instead (chapter 13).
  • Full at, Disks hot at and Other sensors at: limits for this device only. Empty uses the limits under Alerts. A limit here also wins over the iDRAC's own warning level.

  3. The Connection URL (can be an internal address) and a status check.
  4. The integration and its API key, then Test.

Chapter 12

Admin: alerts

  1. Add a channel and press Send test: push to the app, ntfy, Telegram, Discord, e-mail, iMessage (Sendblue) or a webhook.
  2. For each alert type (offline, service down, hardware, storage, temperature, space, TrueNAS, power, container, check-in, backup), pick the channels and a wait time so short blips stay quiet.
  3. Choose whether to send a message when it clears, and reminders while it lasts.

Several alerts at once go out as one message. At most 30 messages go to one channel per hour.

Push to the app

  1. Add a Push to the app channel and save it.
  2. On each phone, tablet or computer, open this channel and press Turn on for this device; allow notifications.
  3. On iPhone and iPad, install the app on the Home Screen first and do it inside the app (iOS 16.4 or newer).

Messages are encrypted so only your device can read them. A critical alert stays on screen, and one open problem has an Acknowledge button.

Acknowledge

Acknowledging means someone is on it: the problem keeps showing until it clears, but the reminders stop. Every channel carries an acknowledge link for a single open problem: a button in push and ntfy, a link in Telegram, iMessage, e-mail and Discord, and ackUrl in a webhook. The link opens a page that asks first, so a link preview can't acknowledge anything, and it only works for that one problem. On Home, use the clock button on the row.

The links point to the dashboard's address. If you reach it by a name, set Dashboard address (chapter 15), so the links work from a phone.

Webhook

A JSON POST for Home Assistant, n8n or Node-RED, with severity, title, text, link, ackUrl and the list of alerts. The URL is stored like a password, because its path is often the secret.

Chapter 13

Admin: check-ins and maintenance

Check-ins

A check-in catches the backup or cron job that silently stopped running. Give it a name, how often the job runs and how late it may be. Then add its address to the end of the job:

0 3 * * * backup.sh && curl -fsS -m 10 http://lookout:8080/ping/… || curl -fsS -m 10 http://lookout:8080/ping/…/fail

It is OK while the job calls in time, Late after the period and Missed after the grace time; …/fail reports a failure at once. Keep the address like a password; New address replaces it.

Maintenance

Plan maintenance for work you know about: Everything, or the devices, services and check-ins it covers; Starting now, Once, or Every week. While it is on, problems are shown as Maintenance, no alerts are sent, and the time doesn't count against uptime. End now stops it early.

Chapter 14

Admin: dashboard, look and power

Dashboard

  • Title, internet provider (and its logo) and refresh interval.
  • Services on Home and VMs and containers: where they show and with which numbers.
  • Status page: switch on the public /status page (chapter 5).
Keep "Make the dashboard public" off unless you really mean it: it shows Home, the rack and services to anyone who can reach the server. Share the status page instead.

Look

  • Theme (21) and accent: the default look for everyone.
  • Logo: the default, a built-in icon in a colour, or your own image (PNG, JPEG, WebP or SVG). It is shown in the top bar, on the sign-in page and as the browser tab icon.
  • The app icon is drawn from the logo on the theme's colour when you press Save. A phone that already has the app keeps its old icon: on iPhone, remove the app and add it again.
  • Background image or gradient, blur, dimming and card opacity.

Power & cost

Choose Norgespris or spot price with your price area, VAT, markup and subsidy. Enter your grid company's day and night rates, the fixed monthly costs and fees.

Include estimated power in cost decides whether devices without a sensor count.

Chapter 15

Admin: backups, security and server

Backups

  • Download now gives one encrypted file with everything, including all passwords. Choose a passphrase of at least 12 characters and keep it in your password manager.
  • Restore reads such a file; the current state is saved first.
  • Automatic backups run daily and can also go to a NAS folder, S3 storage or another machine over SSH.
Moving to a new server: download a backup, install Lookout on the new machine, and restore it. Devices keep their passwords because they travel inside the encrypted backup.

Sign-in & security

  • Admin password: changing it signs out every other browser and remembered device.
  • Passkeys: on the Dashboard address, Add a passkey, name it and confirm with Face ID, fingerprint or PIN. A passkey signs in and confirms risky changes; the password keeps working. Remove deletes one.
  • Signed-in browsers: where you are signed in, normal or kept signed in. Sign out one, or Sign out everywhere else.
  • Remembered devices: the view-only devices, with Sign out for each.

Server

Web server: the HTTPS and HTTP ports. Keep HTTP on Redirect to HTTPS. Certificate shows the names it covers and when it expires, and Download CA certificate is here.

Address & reverse proxy

  • Dashboard address: a domain name, like https://lookout.home.arpa. The dashboard answers on it as well as on its IP, and links in alerts, push and passkeys use it.
  • Reverse proxies: the IP of Nginx Proxy Manager, Caddy, Traefik or another proxy in front of the dashboard. Only these may report the visitor's real address and https, so the lockout and the Log see real addresses.
  • This connection shows what the server sees of your visit and what doesn't add up. Setting up a proxy has copy-ready instructions for each proxy, filled in with your address.

Metrics for Prometheus & Home Assistant

Grafana (through Prometheus) and Home Assistant can read what the dashboard measures: power and energy, temperatures, storage and when it will be full, UPSes, VMs, containers, services, problems and agents. Make a token for each program with the address of the machine it runs on. The token is shown once, with a ready Prometheus config and Home Assistant sensors. It only reads /metrics and /metrics.json, only from those addresses, and never shows addresses or passwords. The list shows when each token was last used, with Change and Remove.

Chapter 16

Keeping it safe

Lookout was built to be safe by default. A few habits keep it that way.

DoWhy
Keep the dashboard privatePublic mode lets anyone on the network see your lab. Share the status page instead.
Use read-only accountsThen even a leaked secret can't change anything.
Pin fingerprintsThe password is only sent to the device you trusted. When one changes, find out why before re-fetching.
HTTPS onlyKeep HTTP on Redirect to HTTPS.
Keep signed in only on your own devicesIf a phone is lost, sign it out under Signed-in browsers.
A unique admin passwordChange it if someone may have seen it.
Treat check-in and webhook addresses as passwordsAnyone who knows one can use it.
Use a socket proxy for DockerNever give the dashboard the Docker socket itself.
Store the backup passphrase safelyA backup holds every password Lookout knows.
Look at the Log now and thenFailed sign-ins and unexpected changes show up there.

Secrets are encrypted on disk (AES-256-GCM) and never sent back to the browser. A form only says whether one is set. Changing a device's address or user name without retyping its password deletes the old password, so it is never sent somewhere new.
